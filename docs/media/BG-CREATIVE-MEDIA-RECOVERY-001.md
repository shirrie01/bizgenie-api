## End-to-end traces and root causes

**Image:** customer Bearer identity → project/approved-brand authorization → immutable image.normal job → entitlement/policy reservation → Image service + Brand Brain → OpenAI generation or edit with rights-aware references → private durable store + media row → completed/pending response → debit. Admin routes require ADMIN_KEY but lack a customer job/reservation path; durable media save requires trusted lineage and is not a safe substitute for customer execution. Generation status uses memory, while asset authority is durable. Local provider disablement is deliberate: `MEDIA_STORAGE_ENABLED`, `IMAGE_GENERATION_ENABLED` and Billing settings are absent. Customer-reference denial additionally has a real brand propagation defect; model entitlement and current provider compatibility are UNKNOWN, not declared broken.

**Video:** customer authorization → immutable video.normal/premium job → reservation → service creates queued durable record → rights-aware GCS image/reference resolution → one `predictLongRunning` operation → submitted/processing → authorised POST poll → existing operation → private prefix-restricted copy + asset row → completed/pending → one debit. GET reads stored status and can reconcile terminal financial settlement; it does not advance the provider operation. Failure releases reservation; transport uncertainty is not permission to resubmit. The historical request incompatibility was repaired in #42. Current flags are intentionally absent locally; polling automation, current provider access/quotas and current deployment configuration are separate UNKNOWN/MISSING boundaries.

**Hybrid:** campaign generate accepts an execution brief and brand-owned reference image IDs → reference/preview-right checks → text-only strategy and draft generation → attempts to save reference IDs in text `asset_refs` → canonical generated-media-only/same-format guard rejects them. The reference lookup is correctly restrictive; weakening it would be a security regression. `execution_mode=human` rejects deliberately. No video compositing/actor/voice/consent engine is hidden behind this enum. Repair needs an agreed distinction between supplied input provenance and output render assets, using existing job execution provenance and revision architecture; it is larger than the permitted brand handoff fix. Also no customer reference ingest/delivery path is present. Do not claim hybrid generation is recovered after a scalar whitelist test passes.

**Additional authority distinction:** `findAuthorizedReference` checks tenant/project, active state, kind and rights for generated assets, but does not join their generation job to require the requested brand. Reference-source assets do require exact recorded brand. Campaign import has a stricter generated-job brand join. Cross-brand reuse of generated inputs therefore needs an explicit policy/security review; it is not fixed or newly authorised here. The bounded repair below does not claim to add generated-asset brand isolation.

## Secure media-delivery contract proposal (not implemented or activated)

Reuse `media_assets`, immutable generation jobs, campaign revision links, existing authorization and GCS storage; no duplicate bucket/adapter/service.

1. Prefer an authenticated API byte route bound to campaign/variant/revision/asset, with scope plus expected campaign version as in #205. Re-read current rights/revocation and confirm the exact asset belongs to that revision's manifest/generation job and brand. Deny foreign/missing/revoked uniformly before storage IO. Generated asset brand derives from its immutable job; reference assets require exact recorded brand. Metadata/bytes never confer approval.
2. Serve only existing bytes from the server-controlled bucket/key, typed from an allowlisted stored MIME. Do not accept URLs, arbitrary keys, provider prefixes, callbacks or MIME from request data. Never redirect to private provider locations or expose storage credentials. PNG/JPEG/WebP/MP4 support must match the actual record and decoder contract; don't add audio or SVG implicitly.
3. Define bounded streaming, size checks before and during transfer, connection deadlines, cancellation and safe single-range MP4 handling (206/416, no arbitrary multipart range amplification). Existing internal `download()` buffers the body and is not suitable to expose directly as a large-video streaming endpoint. `MAX_VIDEO_BYTES` is exported, not a proven public transport limit.
4. Use `Cache-Control: private, no-store`, preserve `Vary: Authorization`, enforce exact-origin CORS, safe Content-Type/nosniff and content disposition. Frontend can use authenticated fetch and revoke local blob URLs; video range-aware playback needs a separately tested bearer/session-compatible transport. Do not put access tokens into query URLs. Public buckets are prohibited. Signed URLs are an alternative only after expiry, revocation lag, CORS and sharing risk are explicitly approved; no arbitrary TTL is invented here.
5. GET/HEAD/range reads must not generate, poll a provider, charge execution credits, approve or publish. Return safe 401/404/409/503 boundaries. Validate tests for cross-tenant/brand, stale revisions, revoked use, content/range limits, interrupted transfers and no paid calls.
6. #205 should keep its unavailable/null-URL state until this transport exists and is approved. A future additive response may identify the authenticated delivery operation; it must not claim pixels from receipt metadata. Same-revision acknowledgement/approval and idempotency remain authoritative.

This is a proposal only. Activating storage/runtime access or introducing delivery credentials, infrastructure, upload capture, schema changes or media-player/session changes requires a separate approved work order. No delivery endpoint is added by this audit.

## Bounded repair implemented after the audit

Only the missing brand handoff was repaired. `src/image-generation/service.js` passes the immutable job's `brand_id` to existing reference resolution; `src/video-generation/service.js` overlays that job brand onto its authorised reference-resolution context and forwards it for both input-image and multi-reference modes. Without a job, existing trusted admin-request brand metadata is propagated, but no tenant authority or durable lineage is invented. A job without brand authority cannot fall back to a customer body's brand.

No provider selection, storage, lookup rights, feature flag, Billing policy, generation model, approval guard or hybrid output contract changed. The existing Video assertion was tightened to require the newly carried brand. Tests use the real `RightsAwareMediaReferenceLoader` with an in-memory media repository, mocked storage and mocked provider completions; no network provider calls occur.

Regression proof before the repair: `node --test test/media-recovery.test.js` ran 8 tests, 5 failed / 3 passed. Same-brand image/video reference success and correct brand propagation failed at the baseline; the hybrid characterization already passed by reproducing the intended resource denial.
