# Engagement Intelligence: minimum source contract and read-only integration plan

Engineering proposal for [issue #203](https://github.com/shirrie01/bizgenie-api/issues/203), draft [PR #204](https://github.com/shirrie01/bizgenie-api/pull/204). The [Google Sheets BizGenie Mission Control register](https://docs.google.com/spreadsheets/d/1N4Yf4hgi5a-ZB_VXZ7WSteLyTVWsX14wxmESvCzMtcc/edit) remains canonical governance. This is not a new register, a migration authorisation or launch acceptance.

## Current evidence and precise gap

`campaign_measurements` already has a composite foreign key through tenant/project/brand/campaign/content-item/variant/publication. `measurementRegistry.listBrand` and scoped `repository.getCampaign` can find the canonical records. Publication records bind the approved revision and approval; variants hold platform/placement/destination. `projection.latestCorrection` resolves the effective publication time. These sources provide a structural join, not a verified analytical join.

The production measurement schema permits only `customer_attestation`, not platform verification. It records a metric, unit, value, `observed_at`, `recorded_at` and `recorded_by`; it does not record the metric's measurement interval or organic/paid basis. Campaign `goal` is free text. Recommendation `goalKind` and `recommendationStrategy` interpret prose for draft suggestions; neither is an authoritative outcome classification. Publication records do not contain a creative-family classification. No existing persisted source was found that closes these gaps.

The public `safeMeasurement` response drops scope/publication metadata and is unsuitable as the adapter's source. Free-text `note`, JSON `intent`, recommendation prose and publication URLs must not be repurposed into an unversioned metadata store. A publication URL does not prove platform analytics access or attribution.

## Minimum data needed

Names below already used by the pure evaluator retain their meanings. Additional version/provenance requirements are proposals for review, not implemented columns or API fields.

| Data | Minimum invariant | Existing authoritative source / remaining gap |
| --- | --- | --- |
| Scope and permission | Verified actor authorised for tenant/project; brand belongs to that scope. Every row must match, including rows excluded by time filters. | Existing customer token/authorization chain, scoped repository reads and measurement foreign key. Never trust request-body ownership. |
| Publication binding | Nonempty canonical campaign, content item, variant and publication IDs; matching publication revision and approval IDs. | Campaign repository publication/approval/revision maps and variant ownership. Use publication's historical revision/approval, not the current draft. |
| Publication time | Effective corrected `published_at`, plus the correction identity and repository snapshot/version used by the adapter. | `projection.latestCorrection`; correction time/version must come from the same read snapshot as other metadata. Re-evaluate on correction; do not rewrite old measurements. |
| Platform cohort | Canonical platform, placement and destination key; no raw cross-platform, cross-placement or cross-account pooling. | Canonical variant. Unrecognised `other` platform cannot establish metric comparability. |
| Objective | Supported typed objective bound to publication/revision, with versioned owner-approved metric and qualification definition, effective timestamp and recording actor. Current pure-policy keys: `retailer_leads`, `qualified_retailer_enquiries`, `wholesale_enquiries`, `bookings`, `sales`. | **Missing authoritative binding.** Free-text `goal` is insufficient. The existing policy mapping to leads/enquiries/conversions/sales is a draft guardrail, not proof that a reported lead is qualified or a conversion is a booking. |
| Observation identity | Stable measurement ID, full publication scope, original source kind, recording actor and timestamps. | Existing registry. Reject duplicates/contradictory snapshots; never relabel customer attestation as platform verification. |
| Metric definition | Count unit, nonnegative bounded integer value for supported outcome/exposure, and an explicit versioned meaning and attribution rule shared by the cohort. | Metric/unit/value exist. Definitions of qualified outcomes and attribution are **missing**. Generic reach, conversions or sales labels alone are not enough. |
| Measurement interval | Explicit timezone-bearing `period_start < period_end`, a half-open interval inside the evaluation window; publication must precede the interval end; interval end no later than `observed_at <= recorded_at <= as_of`. Exposure and outcome share interval and snapshot instant; intervals agree across publications. | **Missing.** `observed_at` is when the value was observed; `recorded_at` is when it was recorded. Neither proves what time span the counter measures. Never derive the interval from either timestamp. A lifetime counter needs an explicitly attested lifetime start and is not an interval delta; never subtract/sum snapshots to invent window counts. |
| Traffic basis | Explicit `organic` or `paid`, supported by the source, for both publication context and selected metric snapshot; no combined/unknown default. | **Missing.** Do not infer organic from manual publishing or lack of recorded spend. If a source provides only combined analytics, return insufficient data. |
| Creative family | Explicit classification bound to the published revision, with recording source/version. Required only to establish repetitive creative and suggest reduction. | **Missing.** Never infer repetition from post count, generic format or an arbitrary ID. Absence cannot establish repetition. |
| Evaluation coverage | Explicit evaluation `window: {from,to}` and `as_of`; complete authorised enumeration of potentially relevant publications, including unmeasured ones, for the requested cohort. | Can be enumerated through scoped campaign reads, but typed objective/traffic remain missing. Pagination/truncation must never silently reduce the cohort to measured posts. |

Evaluation windows select observation instants in `[from,to)`. Measurement intervals are separate source facts, not a side effect of that filter. Current policy additionally requires measurement periods inside the evaluation window and exact snapshot/interval agreement; there is no implicit freshness tolerance. Historical as-of reconstruction is not implemented: a future adapter must either supply an authoritative historical snapshot or explicitly support only a current consistent snapshot. A caller choosing an old window does not prove contemporary freshness.

For supported customer-attested inputs, a trusted application adapter must load both measurement and metadata from authorised sources. Supplying the correct strings to the pure function does not authenticate them. `platform_verified`, simulation, combined organic/paid data and missing source definitions remain ineligible. No live provider integration is proposed here.

## Implementation plan using the existing architecture

1. **Approve the source semantics in #203 and Mission Control.** The owner/founder must approve typed objective-to-qualified-outcome definitions, attribution, time-period/counter basis and explicit traffic classification, including unknown handling. Choose the existing capture/recording authority for these facts; do not infer or backfill existing rows. Keep the pure evaluator unreferenced by production callers while this is unresolved.
2. **Separate persistence work order, only after approval.** Extend the existing campaign/measurement architecture with append-only or versioned bindings for the approved facts, linked to canonical publication/revision and recording actor. Reuse current authorization/idempotency patterns. Any required schema migration and capture/UI change needs its own reviewed authorisation; no migration file is added or changed by this continuation, and no migration is applied to an application/shared database. Existing integration tests initialise only disposable fixture databases. Historical records lacking facts stay unknown.
3. **Add one read-only repository operation.** Reuse the existing PostgreSQL repository's `_read` boundary (already `REPEATABLE READ READ ONLY`) and pool to obtain observations, publication/variant/revision/approval metadata and the effective correction in one consistent read transaction (or prove a version-stable equivalent). Do not stitch independently changing snapshots together with separate `listBrand`/`getCampaign` calls. Use the in-memory repository for deterministic parity tests. Enumerate unmeasured publications as well as measurement rows. A new parallel campaign authority is unnecessary.
4. **Translate without enrichment by guesswork.** Validate IDs and time values with existing campaign schemas. Use recorded metric meanings, objective, interval and traffic metadata. Preserve `customer_attestation`; reject missing or conflicting joins with stable insufficient-data reasons. Never drop positive outcomes because a denominator is missing or zero. Return only IDs of the selected source measurements; expose no recording credentials or raw source payloads.
5. **Integrate only after its gates pass.** Use the existing authenticated scoped learning/recommendation flow behind an explicitly disabled activation gate. Keep manual customer review and all existing generation/publishing/billing boundaries. No automatic cadence mutation. Test tenant/project/brand isolation, metric-definition versions, unknown metadata, correction races, complete pagination, stale/conflicting snapshots and adapter purity before activation review.

The next actionable blocker is step 1: an approved source/definition contract and capture authority. A read-only adapter cannot manufacture the missing facts, and accepting them as arbitrary request fields would bypass their authority. No new schema, endpoint, external integration, infrastructure or activation flag was introduced to hide this blocker.
