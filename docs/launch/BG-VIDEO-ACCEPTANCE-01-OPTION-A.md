## One submit, at most four status observations, lifetime 500p

`FounderVideoSpend` reuses the existing monthly ledger and global transaction advisory lock. A durable namespace keyed to the founder user/tenant binds the first reserved quote/job; another quote/job cannot reset or split it. All bounds in that namespace count toward 500p forever, including cancelled, failed, uncertain and settled rows across month boundaries. The original £100/month, ten-customer guard is unchanged. Reservation and dispatch-start checks execute under the same aggregate lock.

Submit ID is deterministic per quote; no retry/request ID, fence change or restart permits a second submit. Status observation IDs derive from the existing locked worker row's `updated_at`, propagated through fenced transport admission. The worker's successful pending-result recovery updates that durable timestamp, allowing the next explicitly bounded observation. Duplicate same-observation calls share one permit; stale observations are rejected before dispatch. At most four observations receive permits, and fewer if remaining verified budget is insufficient. Equal timestamps fail closed rather than permitting duplicate calls.

Each potentially billable status call reserves its own conservative positive GBP bound before network access. No status call is assumed free: no authoritative free-poll evidence is supplied. Pricing needs sourced/versioned/unexpired units (`second` submit, `request` status), native price upper bounds, fees and current verified FX; missing/unknown/stale authority denies dispatch. A successful HTTP response retains the full monetary bound and records only an internal receipt marker, never response contents. A new observation requires that receipt for submit and all previous observations. HTTP failure, timeout, lost receipt commit or ambiguous outcome holds subsequent observations. Malformed success payloads cannot advance the worker's observation timestamp. No uncertain exposure is freed or budget recycled.

Four observations are an upper bound, not a promise of provider completion.
