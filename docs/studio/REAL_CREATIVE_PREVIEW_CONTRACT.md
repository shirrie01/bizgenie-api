## Request

`GET /customer/campaigns/:campaignId/variants/:variantId/creative-preview`

Required query parameters:

| Parameter | Meaning |
| --- | --- |
| `tenant_id`, `project_id` | Existing customer scope, checked against the verified bearer identity. |
| `revision_id` | Exact current immutable revision UUID. |
| `expected_campaign_version` | Nonnegative decimal integer, at most 2147483647; must equal the campaign snapshot version. |

Requires the existing verified Supabase customer Bearer token and `project:read` authorization. An administrator key is insufficient. Unknown query fields and malformed identifiers/versions return 400. There are no body fields, idempotency keys, writes or provider calls.

Example response shape (illustrative content only; implementation always loads persisted values):

```json
{
  "preview": {
    "contract_version": "campaign-creative-preview.v1",
    "campaign_id": "<canonical campaign UUID>",
    "campaign_version": 3,
    "content_item_id": "<canonical content item UUID>",
    "variant_id": "<canonical variant UUID>",
    "revision_id": "<current revision UUID>",
    "revision_number": 1,
    "platform": "instagram",
    "placement": "feed",
    "content_type": "text",
    "workflow": "review",
    "content_status": "available",
    "copy_status": "available",
    "copy": {"title": null, "body": "<exact saved copy>", "caption": null, "alt_text": null},
    "media": [],
    "provenance": {"source": "persisted_revision", "revision_source": "manual", "created_at": "<stored timestamp>"},
    "approval_status": "not_approved",
    "platform_preview": {"status": "unrendered", "artifact_url": null, "reason": "NO_PERSISTED_PLATFORM_ARTIFACT"},
    "acknowledgement_status": "not_acknowledged",
    "read_only": true
  }
}
```

`copy_status` reports whether any saved copy exists; empty/null copy is never replaced with generated fallback text. `content_status` is `available` for copy-only content with saved copy. It is `unavailable` when media is required/referenced because this change supplies no media transport. Copy can still be displayed when overall media content is unavailable. These statuses are availability facts, not permission or completeness checks for approval.

Each authorised image/video reference has this bounded shape:

```json
{
  "asset_id": "<persisted referenced UUID>",
  "role": "primary",
  "media_kind": "image",
  "mime_type": "image/png",
  "source_kind": "generated",
  "status": "unavailable",
  "reason": "PRIVATE_MEDIA_DELIVERY_UNAVAILABLE",
  "url": null
}
```

Media is rechecked for active status, tenant/project/brand, generation job, media kind, `campaign.preview` rights and the manifest hash already bound to the revision's generation link. Generated status comes only from that authorised record. A missing/revoked/foreign/rights-denied/changed asset produces the same generic `ASSET_NOT_AVAILABLE` entry, with `media_kind` and `source_kind` null and no MIME metadata. Only reference IDs already persisted in this authorised campaign are returned. No storage keys/buckets, job IDs, prompts, ownership columns, internal events, profile/input/content hashes, credentials or fabricated asset URLs are exposed.

`approval_status` is `approved` only for a recorded approval of this exact variant/revision (including a publication's historical approval when appropriate). It is not an authorization to publish or an assertion that a retired profile is currently usable. `acknowledgement_status` reflects this requesting actor's matching revision/content/platform/format acknowledgement with a currently active profile. Neither status can be written through GET. `platform_preview.status` remains `unrendered`: an existing receipt is metadata, not persisted visual rendering. Do not advertise platform-perfect imagery based on this field.

## Errors, consistency and safeguards

- 401: missing/invalid customer identity. 404: denied scope, foreign/missing campaign or variant; no copy in errors. Authorization precedes campaign lookup.
- 409 `VERSION_CONFLICT`: requested version or current revision changed. The endpoint does not silently show a newer revision than requested. Reload the campaign and fetch again with its fresh version/revision.
- 503: sanitized transient repository/media-resolution failure. GET can be retried without an operation key or state change. Missing individual media is a 200 response with explicit unavailability, not a fabricated successful asset.
- `Cache-Control: private, no-store`, `Vary: Authorization` (preserving other Vary values). Do not put authenticated creative in shared caches.
- PostgreSQL campaign, revision, generation-media and active profile checks run in the existing authorised `REPEATABLE READ READ ONLY` transaction. Media resolution uses no row locks on this path; mutation paths retain their existing `FOR SHARE` locking. In-memory tests use the same DTO projection.
- GET does not mint a receipt, acknowledge content, approve, change campaign version, create events, debit credits or contact storage/AI/social providers. Existing `POST .../preview-renders`, `.../preview-acknowledgements` and `.../approval` request/response contracts and idempotency/version checks are unchanged.

## Claude/frontend integration requirements for web PR #34

1. Add a GET client using `URLSearchParams` with session scope, `campaign.version` and `variant.current_revision_id`. Keep the current POST render/acknowledge/approve flow and its operation keys. GET is not a replacement receipt.
2. Fetch creative before showing the review acknowledgement step; display exact saved title/body/caption/alternative text as escaped text, never `dangerouslySetInnerHTML`. Treat platform/placement as metadata for the app's layout, not proof of an external platform screenshot. Provide accessible loading, error and retry states.
3. Keep response state keyed by campaign ID, variant ID, revision ID **and campaign version**. Cancel/discard late responses after navigation or revision/version changes. After acknowledgement/approval, use the newly returned campaign version and refetch if needed; those commands legitimately increment the aggregate version.
4. On 409 clear stale creative/receipt/preview IDs and use the existing reload action. On 401 follow the existing session refresh path; do not fall back to admin authentication. Retry 503 without inventing content. Show unavailable media explicitly and do not enable claims that the reviewer saw an image/video when no bytes are available.
5. Continue sending the exact current receipt/revision/version for acknowledgement and the returned preview ID/current version for approval. Preserve wording that approval does not schedule or publish anything. Rendering/GET success alone must never auto-acknowledge or approve.
6. Add frontend tests for actual saved copy, null/empty copy, unavailable image/video, stale and late responses, error/retry, keyboard/screen-reader flow and unchanged approval guards. No actual browser/frontend QA is claimed by this backend task.

## Remaining boundary

Actual private image/video delivery and persisted platform-rendered artifacts are not implemented. They require a separately approved authenticated delivery contract using existing storage, rights/revocation controls and runtime credentials if necessary. No credentials, migration or paid service is requested or introduced here. Persisted text and authorised reference metadata are safely available now; a full premium visual media preview remains blocked. Text generation provenance cannot be strengthened without a trustworthy persisted source link. No migrations, new dependencies, environment variables, infrastructure, deployments, traffic changes or live generation/publishing calls.
