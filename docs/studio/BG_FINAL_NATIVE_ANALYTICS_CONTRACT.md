# Native analytics and durable Learning collection — code only

9 November 2026. Extends the existing DurableLearningService, platform_performance_observations, snapshots, recommendations and feedback tables. No replacement Learning Brain, migration or provider activation. The earlier five-case reference registry remains a separately labelled in-memory contract; it is not the production store.

## Customer contract

POST /customer/insights/collect uses the existing verified customer JWT and trusted tenant/project/brand scope; owner-only authorization is checked inside the database transaction. Request: {connection_id: UUID, from: ISO datetime, to: ISO datetime, collection_confirmed: true}. Strict schema forbids customer-supplied metrics/account IDs/consent assertions. Window must end in the past, be positive and at most 24 hours (BizGenie collection budget, not a provider limit). Response: contract_version native-analytics-collection.v1, state recorded/partial/withheld/empty, stored/replays/withheld counts. These are ingestion counts, not engagement metrics. Existing router error envelope is retained. JWT failure401; invalid input400; collection disabled503; source unauthorized403; collector unavailable503; provider read unavailable503; invalid batch422. Partial observations are withheld, never synthesized.

LEARNING_NATIVE_COLLECTION_ENABLED defaults OFF and requires existing LEARNING_ENABLED/SOCIAL_PUBLISHING_ENABLED plus a reviewed injected connector. There is deliberately no bridge allowlist entry or polling worker. Existing connectors do not yet expose a verified collector, so startup fails closed if the flag is enabled with current factories. No production traffic, credentials or source was activated.

## Server-owned connector contract

collectionContract native-analytics-collection.v1; requiredScopes; dictionary.version and metric/unit/attribution definitions; learningPolicy.minimumSampleSize (positive integer); fetchObservations({connection,from,to,limit:25,signal}); verifyObservation({connection,publication,observation}). The adapter must bind the server-owned account and verified published dispatch to native record IDs, supply genuine observations and sample metadata, honor abort, bound bytes before parsing, and perform no writes/retries. Provider scopes, lawful basis, dictionary, thresholds, actual API/version and native account/post join must be independently verified before an adapter is composed. No such platform permission is claimed by this mock-tested seam.

The service uses a 10-second deadline and at most25 observations per explicit owner request; empty and sparse results are honest. No automatic retries or cross-instance scheduler is introduced. Concurrency/provider quota and raw-response bounds belong to the reviewed adapter/ingress before activation, not a claim that a returned array bounds provider allocation. Owner confirmation is collection intent; it does not replace GDPR/lawful-basis review or platform consent. Existing connection scope, expiry and revocation are checked before reading and inside each persistence transaction after reading. Membership revoked during collection cannot authorize subsequent commits. Already committed rows remain governed by existing snapshot/source checks; a batch is intentionally not all-or-nothing.

## Durable evidence and Learning

Existing ingest verifies published dispatch, tenant/project/brand, campaign/variant, current customer-approved objective version, platform/account, source verification, timestamps, unit, attribution and dictionary. Existing unique source identities and fingerprints provide replay/correction protection. No token or raw provider response is persisted in observations. Measurement dictionary, attribution policy and audience/cohort must match before comparison. Sparse samples are withheld at collection. Future recommendations reuse existing fresh/current evidence validation, customer acceptance/rejection and bounded accepted-learning context. Differences remain observations/correlation, never causal performance claims. Disconnection/retraction invalidates future evidence use; retention/deletion and backups still need the existing operational retention approval, not an invented purge guarantee.
